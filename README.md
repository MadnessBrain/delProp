# Документация проекта delProp (v1.1.5)

**delProp** — это браузерное расширение (Manifest V3) для оптимизации и улучшения внутренних веб-ресурсов КБ «Вымпел» (включая основной корпоративный портал и электронный архив документов). 

---

## 📂 Структура каталогов и файлов

* **[manifest.json](file:///d:/Projects/delProp/manifest.json)** — конфигурационный файл расширения MV3. Задает разрешения (`storage`, `activeTab`, `tabs`), декларативное объявление фоновых скриптов и контентных сценариев для соответствующих доменов (`*://*.vympel/*` и `*://archive.vympel/*`).
* **[background.js](file:///d:/Projects/delProp/background.js)** — фоновый сервис-воркер. Управляет динамическим внедрением JS-файлов, CSS и обработкой запросов из других контекстов расширения.
* **[build.js](file:///d:/Projects/delProp/build.js)** — скрипт сборки проекта. Выполняет:
  - Очистку папки назначения (`dist/full` и `dist/archive`).
  - Минимизацию JavaScript и CSS с помощью `esbuild`.
  - Обфускацию строковых литералов (кодирование в Base64) для защиты от анализа кода.
  - Генерацию и инъекцию подписи целостности кода (контрольной суммы) для архивной версии.
* **[popup.html](file:///d:/Projects/delProp/popup.html) / [popup.js](file:///d:/Projects/delProp/popup.js) / [popup.css](file:///d:/Projects/delProp/popup.css)** — пользовательский интерфейс настроек расширения и панель учета отгулов.
* **[db/db.json](file:///d:/Projects/delProp/db/db.json)** — локальная база данных, содержащая список новостей расширения (`custom_news`).
* **[patch/patch.js](file:///d:/Projects/delProp/patch/patch.js)** — вспомогательный скрипт, внедряемый напрямую в глобальный контекст страницы (`DOM`), для обхода изоляции песочницы контент-скриптов Chrome. Считывает глобальные переменные страницы (например, `USER_DATA`) и получает историю логов активности с корпоративного сервера.

### Каталог `home/` (Улучшения для основного портала)
* **[core.js](file:///d:/Projects/delProp/home/core.js)** — ядро расширения на портале. Инициализирует глобальные пространства имен, кэширует настройки, предоставляет общие хелперы времени и рассчитывает линейный процент прохождения рабочего дня.
* **[misc.js](file:///d:/Projects/delProp/home/misc.js)** — содержит Mutation Observer для отслеживания изменений на странице, логику расчета переработок по официальным логам и обработку модального окна просмотра изображений.
* **[news.js](file:///d:/Projects/delProp/home/news.js)** — логика очистки стандартных новостей и встраивания кастомного новостного блока расширения с возможностью ручного скрытия записей.
* **[header.js](file:///d:/Projects/delProp/home/header.js) / [header.css](file:///d:/Projects/delProp/home/header.css)** — плавающий центрированный виджет вверху страницы (65% ширины экрана), отображающий текущего пользователя, время его прихода, задержку, прогнозируемое время выхода и интерактивный прогресс-бар рабочего дня.
* **[pivo.js](file:///d:/Projects/delProp/home/pivo.js) / [pivo.css](file:///d:/Projects/delProp/home/pivo.css)** — дополнительные стили и элементы визуального оформления портала.

### Каталог `archive/` (Улучшения для архива)
* **[saveAddres.js](file:///d:/Projects/delProp/archive/saveAddres.js)** — контент-скрипт архива. Отвечает за сохранение истории посещенных вкладок в локальное хранилище и автоматическое открытие последнего открытого документа при запуске архива. Содержит систему проверки целостности кода (защита от модификаций).

## ⚙️ Логика работы ключевых функций

### 1. Передача данных через границы песочниц (DOM Bridge)
Поскольку расширения Google Chrome выполняют контентные скрипты в изолированном окружении, они не могут напрямую читать JS-переменные страницы (такие как глобальный объект `USER_DATA`).
Для решения этой проблемы:
1. `background.js` внедряет тег `<script src="patch/patch.js">` непосредственно в тело страницы (`document.body`).
2. `patch.js` выполняется в контексте страницы, считывает `USER_DATA` и асинхронно запрашивает логи активности с корпоративного сервера `http://pcserv.vympel/get_activity2.php`.
3. Полученные данные записываются в дата-атрибуты создаваемого скрытого элемента `<div id="user">`:
   - `data-user` (JSON-строка данных сотрудника);
   - `data-activity` (JSON-строка истории входов/выходов за текущий месяц);
   - `data-input` (время сегодняшнего логина).
4. В контент-скрипте `misc.js` зарегистрирован Mutation Observer (`userDetector`), который обнаруживает появление элемента `#user`, извлекает эти атрибуты и сохраняет их в `chrome.storage.local`.

### 2. Расчет переработок в отгулы (`processActivityOvertimes`)
Функция расположена в **[misc.js](file:///d:/Projects/delProp/home/misc.js)** и запускается при обновлении истории активности:
```javascript
function processActivityOvertimes(rows) { ... }
```
**Алгоритм расчета**:
1. Считываются настройки рабочего времени пользователя (стандартное время начала смены `startDay`, окончания `endDay` и сокращенного дня в пятницу `endDayF`).
2. Массив `rows` логов перебирается построчно. Из каждой записи извлекается дата, время входа (индекс 2) и время выхода (индекс 3).
3. **Фильтрация выходных**: Пропускаются субботы и воскресенья.
4. **Черный список**: Если дата содержится в массиве `deletedOvertimeDays` (дни, которые пользователь вручную скрыл в попапе), запись игнорируется.
5. **Смещение смены (Опоздания)**: Вычисляется время опоздания `lateness = loginTime - startDay`. Если `lateness` больше 0, но не превышает 30 минут, стандартное время окончания смены сдвигается вперед на величину опоздания. Если опоздание больше 30 минут, сдвига не происходит (считается прогулом части времени).
6. **Ограничение времени**: Время выхода ограничивается сверху 19:00 часами (`1140` минут от полуночи). Все время активности после этого лимита не учитывается.
7. **Вычисление переработки**: Находится разница между фактическим выходом из системы (с учетом лимита 19:00) и рассчитанным (с учетом смещения) временем окончания смены.
8. Если разница положительная, день сохраняется в базу `overtimeDays` с указанием минут и поминутных слотов активности. Если разница отрицательная или нулевая, день удаляется из хранилища.
9. **Начальный баланс месяцев**: Из последней строки логов (при отсутствии в ней даты) извлекается значение перенесенного баланса на начало месяца (предпоследняя ячейка). Оно конвертируется в минуты и сохраняется в `carryOverMinutes` для последующего суммирования в попапе.

### 3. Интерактивная инфо-шапка (`header.js`)
* Отображается только если включена настройка `headerEnabled`.
* Сжимается по горизонтали до `max-width: 65%` и центрируется (`left: 50%; transform: translateX(-50%)`).
* Выводит значок пользователя, настроенный через селектор эмодзи в попапе (сохраняется как `userIcon`, по умолчанию `👤`).
* Имеет два состояния:
  - **Развернутое**: Полноценный плавающий виджет. При клике в любой области виджета запускается анимация скрытия, и состояние `headerMinimized` сохраняется как `'true'`.
  - **Свернутое (Минимизированное)**: Шапка скрывается за пределы экрана вверх. По центру в самом верху страницы появляется компактная кнопка-триггер `▼`. При клике на триггер панель выезжает обратно.

### 4. Очистка и управление новостями (`news.js`)
* **Официальные новости страницы**: Если в настройках активирована опция `dellNewsField.news === 'true'`, все стандартные новости портала (`.dhx_list_item` без класса `.delprop-custom-news`) немедленно удаляются из контейнера при рендеринге. В противном случае к каждой новости прикрепляется кнопка-крестик `×`. При нажатии на крестик ID новости заносится в локальный массив `newsList` в хранилище, и в будущем она скрывается.
* **Восстановление новостей**: В попап-меню настроек выведена кнопка «Восстановить скрытые новости», которая очищает массив `newsList`, возвращая все скрытые элементы обратно в ленту.
* **Кастомные новости расширения (из `db.json`)**: Всегда выводятся вверху списка новостей. На них не влияет глобальный переключатель удаления новостей. Каждая кастомная новость имеет крестик для ручного закрытия, который записывает её ID в список скрытых.

### 5. Контроль целостности кода в архиве (Anti-Tamper)
Для защиты архивной версии от несанкционированного изменения кода в **[build.js](file:///d:/Projects/delProp/build.js)** и **[saveAddres.js](file:///d:/Projects/delProp/archive/saveAddres.js)** встроена система автоматического самотестирования:
1. Во время сборки в конец файла `saveAddres.js` помещается маркер `// INTEGRITY_SIGNATURE:00000...` (32 нуля).
2. Скрипт сборки заменяет маркеры на 32-символьный шестнадцатеричный хэш, вычисленный по алгоритму хэширования строки (аналог Murmur/DJB2), предварительно заполнив область сигнатуры пробелами для чистоты вычислений.
3. При запуске расширения в браузере скрипт с помощью `fetch` считывает свой собственный исходный код с адреса `chrome.runtime.getURL('archive/saveAddres.js')`.
4. С помощью метода `txt.lastIndexOf('INTEGRITY_SIGNATURE:')` находится позиция хэша в конце файла. Код разделяется на части до и после хэша, а сам хэш временно заполняется пробелами.
5. Вычисляется контрольная сумма полученной чистой строки. Если она не совпадает с зашитым внутри файла значением `INTEGRITY_SIGNATURE`, скрипт очищает страницу (`document.documentElement.innerHTML = ''`), перенаправляет вкладку на `about:blank` и выбрасывает исключение безопасности.

## 🛠️ Сборка проекта
Для минимизации и обфускации кода архивной версии используется скрипт сборки:
```bash
node build.js
```
Скрипт создает в корневой директории папку `dist/`, содержащую две сборки:
* `dist/full/` — полная версия расширения со всеми инструментами и открытым исходным кодом.
* `dist/archive/` — специализированная облегченная версия только для архива, содержащая минимизированный, защищенный подписью и обфусцированный Base64-алгоритмом код.
